# Album Deduplicator Architecture

מסמך זה מסביר את גבולות האחריות, זרימת הנתונים וכללי הבטיחות של המערכת המקומית. התקנה, הרצה ובדיקות נמצאות ב-[README](../README.md); מדיניות תחזוקת התיעוד נמצאת ב-[CONTRIBUTING](../../CONTRIBUTING.md).

## שכבות וגבולות אחריות

| שכבה | אחריות ומקור בקוד |
| --- | --- |
| Core | סריקה, מטאדאטה, hashes, השוואה ואיכות תחת `music_dup_lib/core/` |
| Services | תיאום הניתוח, scoring, clusters, המלצות, החלטות ומחיקה תחת `music_dup_lib/services/` |
| External | מודל ML מקומי וניתוח Gemini אופציונלי תחת `music_dup_lib/external/` |
| API | ניהול sessions, התקדמות ב-SSE והמרת DTOs לתשובות תחת `api/` |
| Desktop | Electron מנהל חלון ושרת מקומי, ו-preload חושף פעולות מערכת מוגבלות תחת `frontend/electron/` |
| Frontend | React ו-Ant Design מציגים תהליך סקירה בעברית ובסגנון דסקטופ תחת `frontend/src/` |

ה-CLI (`main.py`) וה-API משתמשים בשכבת השירותים. כללי ניקוד ומחיקה שייכים ל-backend; ה-renderer מציג תוצאות ובחירות משתמש ואינו מחליף את ההכרעה העסקית.

## זרימת עבודה

1. Electron מעלה backend מקומי וממתין לבדיקת בריאות. ה-renderer מקבל את כתובת השרת דרך ה-preload
2. יצירת session מעבירה roots ואפשרויות ל-`SessionStore`, שמריץ את הניתוח ברקע
3. `AnalysisOrchestrator` מתאם סריקה, השוואת זוגות, scoring וקיבוץ. אירועי התקדמות מגיעים לממשק ב-SSE
4. `ScoringService` משלב ניקוד אלגוריתמי עם ML מקומי ומשתמש ב-Gemini לזוגות גבוליים בלבד. חוסר זמינות של ML או Gemini מסומן כ-degraded ואינו מחייב הפסקת שימוש
5. `RecommendationService` בוחר עותק לשמירה לפי העדפת root ואיכות, ומסווג קבוצות ל-`safe` או `review`
6. המשתמש סוקר את העותקים ובוחר מה לשמור ולהעביר. `DeletionService` בונה preview ומבצע את ההעברה לסל המחזור לאחר אישור

## כללי בטיחות

- מחיקה מבוצעת באמצעות `send2trash` בלבד. המלצה אוטומטית אינה אישור לביצוע; גם מחיקה של עותק יחיד דורשת keeper ובדיקות ב-backend
- keeper חייב לכסות ישירות את שאר חברי הקבוצה בקשרים בטוחים; חיבור עקיף בגרף אינו מספיק כדי להצדיק מחיקה
- ספים ומשקלי scoring מוגדרים ב-[config.py](../music_dup_lib/config.py), והכרעת הקבוצה ב-[recommendation_service.py](../music_dup_lib/services/recommendation_service.py). אין לשנות מדיניות מחיקה על סמך ציון ML לבדו
- hash חלקי הוא ברירת המחדל; אפשר לבקש full hash. ציון דמיון או התאמת hash חלקי אינם הוכחה סטטיסטית לאפס סיכון. מגבלות הוולידציה מוסברות ב-[ML_VALIDATION.md](ML_VALIDATION.md)
- הסריקה מיועדת לתיקיות אלבום ללא תתי-תיקיות. הרחבת הסריקה לעצי תיקיות דורשת טיפול מפורש בסיכון מחיקת תכולה נלווית
- המערכת מיועדת למשתמש יחיד על מחשב מקומי. אין להתייחס ל-API כשרת מרובה משתמשים עם בידוד והרשאות
- מפתח Gemini נשמר בהגדרות מקומיות; ה-renderer מקבל חיווי על קיום מפתח שמור ולא את ערכו

## מצב בזיכרון ונתונים מתמשכים

`SessionStore` מחזיק session ותוצאות בזיכרון. חזרה למסך ההגדרה יכולה לשמר session פעיל, אך restart של השרת אינו משחזר אותו.

יש להבחין בין שלושה סוגי נתונים:

- cache סריקה והשוואה תחת `data/` ממוחזר רק כאשר שמות הקבצים, הגדלים, זמני השינוי והגדרות החילוץ והניקוד תואמים, כולל העדפת bitrate, המודל והנחיות Gemini. cache ישן ללא חתימה נסרק מחדש פעם אחת; הכתיבה אטומית. חתימות stat אינן מזהות שינוי תוכן שמחזיר גם את הגודל וזמן השינוי המקוריים, ולכן בדיקה מלאה במצב כזה דורשת סריקה מאולצת עם full hash
- החלטות ידניות תחת user-data מאפשרות שחזור בחירות לקבוצה התואמת לסריקה החדשה. הן אינן dataset לאימון; המימוש ב-`services/user_decision_store.py`
- feedback ממחיקות מוצלחות נשמר בנפרד כ-JSONL. המיקום, הפורמט ויצוא הנתונים מתועדים ב-[USER_FEEDBACK_DATASET.md](USER_FEEDBACK_DATASET.md)

אין לתעד כאן כל אופטימיזציה של cache או זיכרון. שינוי בחוזה נתונים או בכללי שחזור דורש עדכון הסעיף הרלוונטי; שינויים פנימיים נשארים בקוד ובבדיקות.
